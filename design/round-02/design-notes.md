## 第 1 轮为什么被否（留档）

第 1 轮三个方向（质检日报 / 蓝晒图纸 / 炉前控制台）全部从**视觉概念**出发：公文、晒图、熔炉都是"贴在产品上的皮肤"，用户指出从使用者角度看有问题。经确认，用户选择"三个方向都不对"，要求以「测试工程师的一天」为第一约束重新起方向。第 1 轮产物保留在 `../round-01/` 留档，不删。

## 第 2 轮的约束（来自用户与真实数据）

用户证据：进来 3 秒要知道今天该处理什么（草稿 39 · 缺陷 21 · 需求 1）→ **人审是阅读密集劳动**（用例正文、缺陷描述）→ 盯失败（web-api 修复 3 轮未过）→ 表单多（仓库/需求/用户）。一天几小时，任务是"处理"，不是"欣赏"。

锁定调性（证据充分，三候选不越界）：**亮色 · 低装饰 · 待办驱动**。差异只在骨架、字体角色、色彩身份：

## 方向卡

### 1 · 今日清单（1-checklist.html）
- 引擎：角色原型"验收员过清单"——用户的核心动作就是勾掉一条。
- 骨架：顶部一行细状态条（指标退居其后）→ 今日总额 + 分项 chips → 单列处理清单，**对象与动作同一行**，完成的划线沉降；空闲组折叠成一行。
- 字体：单一雅黑家族 + 等宽数字，层级靠字重与细线，不用色块。
- 色彩：冷白 #fafbfc + 墨 #1f2328 + 琥珀 #b45309（只给"待处理"）+ 绿 #15803d（只给"已完成"）。
- 主视觉：勾选沉降的清单本身。放弃：卡片、色块、图标语言。
- 适配：人审/缺陷/回归都能装进"行 + 行内动作"范式；工作台类视图下清单变成队列，同构。

### 2 · 审阅台（2-review-desk.html）
- 引擎：用户手上的真实物件——测试用例文档；人审是全平台最重的阅读劳动，给它三栏工作台。
- 骨架：左队列（今日 39 条，进度 4/39）+ 中央**用例正文**（阅读是主角：需求引文块、结构化小节、深色断言代码块、覆盖缺口、RAG 相似提示）+ 右动作栏（通过/打回/转缺陷 + 批注 + 快捷键）。
- 字体：三种文字各司其职——需求原文宋体引文（人话归纸面）、界面雅黑、断言与数字等宽。
- 色彩：米白 #faf8f3 + 墨 #262b33 + 靛青 #2b6cb0（唯一主操作色）+ 朱红只给打回。
- 主视觉：中央阅读版面本身。放弃：装饰、色块导航。
- 适配：同一范式直接覆盖缺陷详情、Wiki 阅读、运行详情；队列即左栏。

### 3 · 值班信号板（3-signal-board.html）
- 引擎：场景"值班室状态板"——测试的另一面是盯：失败必须立刻跳出来。
- 骨架：信号条堆叠（失败置顶 + 状态底色 + 左缘灯条）→ 42px 大数字行（量画出来，通过率 51.2% 红色承担警示）→ 今日执行时间线（失败红点在轴上）→ 待办横条。
- 字体：雅黑 + 大等宽数字，数字是画面的量不只是标签。
- 色彩：近无彩 UI（#f4f6f5 / #172026），红绿琥珀只给状态——黑白灰 + 状态三色也是完整色彩身份。
- 主视觉：信号条与大数字。放弃：品牌装饰色、卡片阴影层次。
- 适配：Runs/Jobs/Quality 天然同构；缺陷页 = 红色信号区；人审页在此方向里退居次要，需另配阅读范式（可借方向 2 的中央栏）。

## 差异检验（已通过）

骨架三种（清单 / 三栏工作台 / 信号板）；字体角色三种；色彩身份三种（琥珀单强调 / 靛青纸墨 / 无彩状态三色）；主视觉三种。任意两个候选至多共享一项（1 与 3 的 UI 字体同为雅黑，但数字角色与主视觉不同）。三者均打破"侧栏 + 卡片网格"套路，均未越出锁定的亮色低调调性。
