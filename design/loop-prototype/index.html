TestForge 知识资产闭环 · 总览

两个入口 → 一条知识脊柱 → 测试业务消费 → 缺陷回流。参照 GitNexus / LightRAG / OpenWiki 取舍落地（2026-10-10）。

闭环全景

落地入口 ① 代码 → 图谱

  • POST /api/repos/upload：zip 上传 → 安全解压（zip-slip 防护 / 大小与成员数上限 / 排除目录清单）→ 复用注册流水线：tree-sitter 索引 → 调用图 → 影响面/聚类 → Wiki 编译
  • 同名重传 = 更新图谱（upload:// 无远端，pull 引导重传）
  • 前端仓库接入页双 Tab：Git URL ｜ 上传代码包

落地入口 ② 知识资产中心

  • 四类统一上传：需求文档 / 技术文档 / 测试方案 / 历史缺陷（pdf·docx·md·txt·csv·xlsx）
  • 解析 → 敏感扫描（修复 kg 管线二进制文档不扫的缺口）→ 评估门卫 → 双写：rag kind 行（即时可检索）+ LightRAG KG 管线（进图谱）
  • 历史缺陷走结构化表 + 摘要索引（LightRAG ainsert_custom_kg 取舍：真相放 defects 表，KG 只做投影，不逐行走 LLM）

三仓库取舍结论（源码级分析）

仓库为这两个入口抄什么为什么不抄
GitNexus
PolyForm NC 禁商用
只借设计不碰代码
 抄zip 通道三件安全栏（名称消毒/root 困定/路径穿越防护）+ 上传前过滤思想；job 式进度协议形状；边 confidence+reason（后续档） 不抄任何代码（License）；浏览器逐文件 multipart 上传 2 万文件（桌面场景产物）；LadybugDB 嵌入库（多租户平台 PG 是对的）；Spring/COBOL overlay
LightRAG 抄统一走异步 KG 管线 + kind 双写（不按 kind 拆 workspace——会打碎图谱与社区）；结构化缺陷「表+投影」姿势；观测四件套列后续档 不抄单实例绑一个 workspace 的多租户方式（多实例部署不适合单体平台）；csv 原文直接 chunk→抽取当唯一表示（行级抽取贵且丢聚合）
OpenWiki 保三信任机制已移植并继续生效：评估门卫 / 反幻觉（无 source 不入库）/ 确定性建边；lint 增加覆盖盲区规则列后续档 不搬剪贴板轮询/OCR/周报（桌面语义）；Jina Reader 外发（企业测试文档不许出网）
已超越TestForge 相对三个原版的共同优势：知识直接进测试生成闭环（生成→执行→缺陷→回流自动召回）、服务端智能体带沙箱、七类 kind 统一检索表 + LightRAG 六模式并存。
