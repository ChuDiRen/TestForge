订单模块（order-module）

职责

  • 订单创建 / 取消 / 查询的生命周期管理
  • 下单价格计算与优惠券核销

对外接口

  • POST /api/orders · DELETE /api/orders/{id} · GET /api/orders/{id}

业务规则

  • 下单金额必须 > 0 且 ≤ 单笔上限 50,000
  • 下单即锁定库存（inventory.lock），取消订单 15 分钟内免手续费
  • 买家与商家角色隔离：买家仅能操作自己的订单
  • 支付预授权失败时订单进入 PAY_FAILED 终态并释放库存

调用关系

  • 依赖：inventory（库存锁定）· payment（预授权）· eventBus（领域事件 OrderCreated）
  • 被依赖：退款模块 · 报表模块

已知风险点（来自历史缺陷）

  • 金额字段曾出现科学计数法绕过上限校验（BUG-2213，已回归用例 TC-009）

业务流：下单 → 支付（跨 3 服务）

链路

  • gateway → order-service → inventory-service（同步 gRPC）· payment-service（同步 REST）
  • order-service → kafka order.created v3 → notification-service（异步）

关键规则（跨服务）

  • 下单即锁库存；15 分钟未支付由 payment_ttl_scanner 自动关单并释放库存
  • 预授权失败 → PAY_FAILED 终态 + 库存释放 + 事件 order.pay_failed
  • 买家与商家角色隔离在网关层统一鉴权（User API v1.0.4）

SLA（来自近 7 天 trace，12,438 条，已脱敏）

  • P99 850ms · 错误率 0.3% · 超时主因：payment 预授权慢调用（占 71%）

契约依赖

  • Payment API v2.4.0 ⚠ breaking → 2 个 wiki 页 stale、5 个用例待定向重生成
  • LockStock gRPC v1.8.0 ✅ 最新 · User API v1.0.4 ✅ 最新

关联用例

public Order createOrder(OrderRequest req, User buyer) {
    validateAmount(req.getAmount());              // 金额必须 > 0 且 ≤ 50000
    if (req.getAmount().compareTo(MAX_ORDER) > 0)
        throw new BizException("EXCEED_LIMIT");
    Item item = inventory.lock(req.getSku(), req.getQty()); // OUT_OF_STOCK
    Order order = Order.of(buyer, item, req.getAmount());
    orderRepo.save(order);
    payment.preAuth(order);                       // PAY_FAILED
    eventBus.publish(OrderCreated.of(order));
    return order;
}
